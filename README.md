# MCSkill HiTech 1.7.10: headless AFK

Клиент на Node.js для protocol **5**, без Java, графики, X11/Xvfb и runtime-зависимостей. Не загружает ресурспаки, не хранит чанки, сущности или историю чата. Для ручного управления хранит только метаданные 45 обычных слотов; NBT не распаковывается и не сохраняется. По умолчанию стоит на месте; отправка чата и сброс вещей выполняются только по введённым пользователем командам. Серверная AFK-политика не обходится.

**Статус:** реальный вход MCSkill, штатная авторизация, Forge/FML и 10 минут в мире проверены на Windows: 292 KeepAlive, 52–53 MiB RSS. Отдельно подтверждён автоматический повторный вход после локального обрыва TCP и ещё минута KeepAlive. Linux/systemd и длительная работа на VPS пока требуют проверки на вашей машине. Результаты и конкретные отличия сборки: [research/REPORT.md](research/REPORT.md).

## Быстрый запуск в Windows

Для **второго аккаунта с логином и паролем** откройте двойным щелчком **`START-BOT.cmd`**. Введите логин и пароль; пароль не отображается. После пароля появится вопрос `Сохранить логин и пароль в приватном файле? [y/N]`. Ответ `Y` сохраняет данные после успешной авторизации; при следующих запусках ввод не нужен. `N` или Enter оставляет данные только в памяти. Используется штатный TLS/gRPC API лаунчера MCSkill, найденный в локальном `Launcher.jar`. `session.json` первого аккаунта и переменные с его токеном не используются и не изменяются.

После успешной авторизации закройте игру **второго** аккаунта и нажмите Enter для подключения. Первым аккаунтом можно пользоваться отдельно, насколько это допускают правила сервера. Остановка бота — Ctrl+C. При истечении сессии запустите файл заново и повторите вход. Если API запросит VK/MFA/TOTP или подтверждение устройства, сценарий остановится: выполните штатное подтверждение через официальный лаунчер. Не отключайте защиту ради бота.

Тот же вход на Ubuntu: `./start.sh`. Данные по умолчанию находятся **вне репозитория**, в `~/.config/mcskill-afk/credentials.json`, Unix-права `0600` (каталог `0700`); на Windows создаётся закрытый ACL текущего пользователя. Пароль хранится в открытом виде: доступ к этому файлу даёт доступ к аккаунту. Можно задать `MC_CREDENTIALS_FILE`. Не публикуйте файл и его резервные копии. Замена данных: `./start.sh --setup`; удаление локальной копии: `./start.sh --forget`. Копия systemd в `/etc/mcskill-afk` управляется отдельно. Новый путь проверен mock-тестами; проверка живого аккаунта и длительной работы остаётся на VPS.

Для альтернативного запуска по ранее подтверждённой сессии нужен Node.js **22.15+** (проверено на 24.13.1). Авторизуйтесь вручную через официальный лаунчер, включая VK/2FA, если они подключены. Закройте игру перед входом headless-клиентом: одновременные подключения одним аккаунтом конфликтуют.

```powershell
npm.cmd ci --ignore-scripts
npm.cmd test
node tools/import-session.js --latest
powershell -ExecutionPolicy Bypass -File tools/secure-session.ps1
npm.cmd run forge-test
npm.cmd run afk
```

Импорт читает только `username`, `uuid`, `accessToken` из последнего `%TEMP%/mc-launch-*.args`. Он не выполняет команды из args, не печатает токен, не копирует пароль, userProperties или всю командную строку. Укажите конкретный файл и место назначения при необходимости:

```powershell
node tools/import-session.js 'C:\path\mc-launch-example.args' session.json
```

На Linux импортёр тоже работает с явно указанным args-файлом, но обычно безопаснее перенести только полученный `session.json` через SSH. Не публикуйте launcher args, сессию или их содержимое. Не передавайте токен аргументом командной строки.

## Режимы

| Команда | Условие успеха |
|---|---|
| `npm run probe` | TCP, Handshake с доменом, получение Encryption Request; сессия не нужна |
| `npm run auth-test` | Штатный MCSkill join и зашифрованный Login Success нужного профиля |
| `npm run forge-test` | FML complete + Join Game + позиция + хотя бы один KeepAlive за 30 секунд |
| `npm run afk` | Поддержание сессии до сигнала, ошибки или серверного отключения |

`probe` использует login handshake, поскольку нестандартный Status этого сервера не является надёжной проверкой. Каждый тест делает одну попытку. Коды завершения: 0 — успех/запрошенная остановка, 1 — ошибка. Для длительной проверки задайте `MC_TEST_DURATION_MS=600000` (10 минут).

Не запускайте циклы probe/auth/forge-test. В AFK по умолчанию после обрыва сети или неудачного подключения клиент ждёт **60 секунд** и повторяет вход **без ограничения числа попыток**. Это действует и для `START-BOT.cmd`. Следующая пауза отсчитывается после завершения неудачной попытки, поэтому время самого подключения добавляется к минуте ожидания. При успешном входе клиент остаётся в мире и больше не переподключается, пока соединение не оборвётся.

Распознаются серверные сообщения о рестарте, технических работах, заполненном или недоступном сервере, в том числе во время Login. **Неизвестный отказ во время `LOGIN` тоже повторяется через минуту:** прокси может принимать TCP и Encryption Request, пока игровой сервер ещё выключен, а затем возвращать общее отключение. В логе такой случай обозначается `SERVER_LOGIN_RETRY`; он не означает неверный пароль. Неизвестный кик уже из `PLAY`, явный отказ авторизации/недействительная сессия, ошибка протокола, AFK-kick и бан останавливают клиент. При запуске через tools/login-and-afk.js истёкшая сессия обновляется через штатный вход с сохранённым паролем; в режиме --session её нужно обновить вручную. Ctrl+C/SIGTERM немедленно прерывает и минутное ожидание. При необходимости доступны ограничение попыток и прежний режим `MC_RECONNECT_MODE=backoff` с jitter; по умолчанию jitter не применяется.

## Чат и ручное управление

В `START-BOT.cmd`, `npm run login` и интерактивном `npm run afk` после входа появляется строка `>`. Получаемые сообщения игроков и сервера выводятся с префиксом `[CHAT]`. JSON-компоненты чата преобразуются в обычный текст, Minecraft-коды цвета удаляются; ссылки и click/hover events не выполняются. Управляющие последовательности терминала удаляются. Приходящие сообщения и диагностические строки сохраняют набираемый текст.

- Обычный текст + Enter — отправить сообщение в чат.
- `/команда` + Enter — отправить серверную команду. Лимит protocol 5: 100 символов, отправка не чаще раза в секунду.
- `:help` — справка по локальным командам.
- `:inventory` — показать известные слоты, числовой ID, damage и количество, без вымышленных названий модовых предметов.
- `:dropall` — показать конкретные стаки для сброса и выдать одноразовый код подтверждения на 30 секунд.
- `:confirm КОД` — подтвердить показанный список. Сам `:dropall` ничего не выбрасывает.
- `:cancel` — отменить подтверждение и оставшиеся действия сброса. Уже отправленное действие отменить нельзя.
- `:quit` или Ctrl+C — остановить бота.

Сброс охватывает слоты 1–44: сетку крафта, **надетую броню**, обычный инвентарь и хотбар. Слот 0 (результат крафта), содержимое рюкзаков, Baubles и прочие модовые слоты не затрагиваются. Вещи падают рядом с персонажем, могут быть подобраны другими игроками или снова оказаться в инвентаре. Автоматического повторного сброса нет.

Клиент отправляет по одному штатному C0E click-mode=4/button=1, ждёт и положительный Transaction, и пустой слот, затем выдерживает минимум 300 ms перед следующим стаком. При отказе, пятисекундном таймауте, смене предмета, открытии другого окна, смене мира или разрыве соединения оставшиеся действия отменяются. Для сброса нужен полный свежий снимок из 45 слотов и пустой курсор. При неподдерживаемом layout или неизвестном состоянии действие запрещено. Если после открытия стороннего окна нет свежего полного снимка, потребуется переподключение. Подтверждения и задания не переносятся на новое соединение.

При потере сети введённые сообщения не накапливаются и не отправляются позже. `MC_CHAT=0` отключает показ входящего чата. В режиме systemd сообщения попадают в journal; ввод команд доступен только в интерактивном терминале — писать в `journalctl` нельзя. Для ручного управления на VPS запустите клиент в SSH-терминале, предварительно остановив сервис этого аккаунта. Поступающий чат не сохраняется приложением в файлы, но терминал и journal могут хранить вывод.

Новые функции проверены автоматическими тестами и зашифрованным mock-сервером. На живом аккаунте отправка чата и сброс вещей при разработке не выполнялись.

## Конфигурация и секреты

Источник сессии: `MC_SESSION_FILE`, по умолчанию `./session.json`. На Linux права файла должны быть **0600**. Альтернатива: одновременно `MC_USERNAME`, `MC_UUID`, `MC_ACCESS_TOKEN`; окружение с токеном имеет приоритет. Файл содержит только поля из [session.example.json](session.example.json). Рекомендуется файл вне репозитория; переменные окружения могут быть доступны администратору и средствам диагностики процессов.

`.env.example` — список переменных, а не автоматически загружаемый dotenv-файл. Локально экспортируйте переменные в оболочке. Для systemd используется `/etc/mcskill-afk/config`.

| Переменная | По умолчанию |
|---|---|
| `MC_HOST`, `MC_PORT` | `titan.skydrive.metalabs.work`, `25565` |
| `MC_SESSION_FILE` | `session.json` |
| `MCSKILL_AUTH_ORIGIN` | `https://auth.mcskill.ru` |
| `MCSKILL_AUTH_MODE` | `modern`; также `legacy` для штатного legacy API |
| `FORGE_PROFILE` | `mcskill`; `standard` для обычного FML 1.7.10 |
| `MC_MODS_FILE` | `profiles/industrial-1.7.10.json` |
| `MC_TIMEOUT_MS` | `30000`, предельное время входа |
| `MC_IDLE_TIMEOUT_MS` | `90000`, отсутствие входящих TCP-данных |
| `MC_TEST_DURATION_MS` | `30000`, время после входа для forge-test |
| `MC_RECONNECT_MODE` | `fixed`; также доступен `backoff` |
| `MC_RECONNECT_INTERVAL_MS` | `60000`, пауза в режиме `fixed` |
| `MC_RECONNECT_BASE_MS`, `MC_RECONNECT_MAX_MS` | `15000`, `300000`, только для `backoff` |
| `MC_MAX_RETRIES` | `-1` — без лимита; 0 — без повторов; положительное число — лимит |
| `MC_STABLE_MS` | `300000` |
| `MC_MAX_PACKET_BYTES` | `4194304`, не больше 16 MiB |
| `MC_CHAT` | `1`, вывод чата; `0` — отключить |

Используйте **домен**, не IP: hostname передаётся TCPShield внутри Handshake. Маркер `\0FML\0` добавляется клиентом. Auth origin ограничен двумя официальными HTTPS-адресами: `auth.mcskill.ru` и `auth.mcskill.net`; HTTP redirects не выполняются, TLS-проверка включена. Токен отправляется только выбранному Auth API MCSkill, не Minecraft-серверу и не Microsoft/Mojang.

## Ubuntu VPS / systemd

Для **Ubuntu 22.04+ x86_64** достаточно клонировать репозиторий, запустить один установщик и затем бота:

```bash
git clone <repository> mcskill-afk
cd mcskill-afk
bash install-ubuntu.sh
./start.sh
```

Если `git` ещё не установлен: `sudo apt-get update && sudo apt-get install -y git`. Команду `bash install-ubuntu.sh` запускайте обычным пользователем: только установка Ubuntu-пакетов и optional systemd потребуют sudo. При работе от root sudo не требуется.

Установщик добавит CA certificates, curl, xz, tar, coreutils, libstdc++6 и tmux из Ubuntu repositories. Он скачает Node.js 24 из [официального каталога Node.js](https://nodejs.org/dist/latest-v24.x/), сверит архив по официальному SHA-256 manifest и разместит runtime в `.runtime/node` внутри проекта. Системный Node.js не заменяется, сторонний apt-репозиторий не добавляется, скачанные shell-скрипты не запускаются. Уже установленный совместимый приватный runtime используется повторно. Затем выполняются `npm ci --ignore-scripts --no-audit --no-fund`, все Node-тесты и Bash smoke-проверка запуска. `.runtime` и временные загрузки исключены из Git; архив исходников их не содержит.

`./start.sh` использует сохранённые данные либо запросит логин, скрытый пароль и согласие на сохранение, затем запустит бота с чатом и ручными командами. Дополнительные варианты:

```bash
./start.sh --tmux      # запуск/возврат в постоянную интерактивную консоль
./start.sh --session   # запуск через MC_SESSION_FILE или ./session.json
./start.sh --probe     # одна проверка сервера, без авторизации
./start.sh --setup     # заменить/сохранить данные без запуска бота
./start.sh --forget    # удалить локальный файл данных
./start.sh --help
```

Для VPS удобен `--tmux`: после входа можно нажать **Ctrl+B, затем D**, чтобы отключиться от консоли, и закрыть SSH. Вернуться — снова `./start.sh --tmux`. [tmux сохраняет сеанс при отключении SSH](https://github.com/tmux/tmux/blob/master/tmux.1). Остановка бота — `:quit` или Ctrl+C внутри его консоли. Это сохранение работающего процесса; после перезагрузки самой VPS требуется новый запуск (сохранённый пароль повторно не запрашивается). Не запускайте этот же аккаунт одновременно в tmux, systemd и обычной консоли.

Повторный запуск установщика обновляет зависимости и проверки, но не меняет Git checkout и не перезапускает работающего бота. Для обновления исходников остановите бота, выполните `git pull`, снова `bash install-ubuntu.sh`, затем запустите его. Проверки устанавливаемого Bash-сценария выполнены через Git Bash на Windows; полный apt/systemd прогон требует Ubuntu VPS.

Для постоянной работы через **systemd** сначала остановите бота в tmux (`:quit`). Затем:

```bash
./start.sh --setup                      # логин, пароль, затем Y
bash install-ubuntu.sh --service
sudo systemctl enable --now mcskill-afk
sudo journalctl -u mcskill-afk -f
```

Установщик создаёт отдельного системного пользователя, копирует приложение и Node.js в `/opt/mcskill-afk`, сохранённые данные — в `/etc/mcskill-afk/credentials.json` с владельцем `mcskill-afk` и правами `0600`. Для обычного пользователя путь исходного файла передаётся через sudo без пароля в аргументах. После SSH-разрыва бот продолжает работу; после перезагрузки VPS стартует сам. Не запускайте параллельно тот же аккаунт в tmux. systemd-консоль показывает логи; ручные команды чата и инвентаря доступны в обычном запуске или tmux, когда сервис остановлен.

Для обновления кода или пароля: `sudo systemctl stop mcskill-afk`, при необходимости `./start.sh --setup`, затем `bash install-ubuntu.sh --service` и `sudo systemctl start mcskill-afk`. Если установленный сервис уже использовал файл сессии, новая установка переводит его на сохранённые данные логина/пароля.

Опциональные настройки без токена:

```bash
sudo install -o root -g mcskill-afk -m 0640 /dev/null /etc/mcskill-afk/config
sudoedit /etc/mcskill-afk/config
# Например: MC_RECONNECT_INTERVAL_MS=60000
sudo systemctl restart mcskill-afk
```

Unit: отдельный системный пользователь, read-only системные каталоги, `MemoryHigh=256M`, `MemoryMax=300M`, JS heap 192 MiB, `CPUQuota=90%`, максимум 32 задачи и 128 файловых дескрипторов. Приложение повторяет сетевые подключения каждую минуту без лимита; ошибки сети при авторизации тоже повторяются. При `AUTH_REJECTED` или явном истечении сессии бот один раз получает новую сессию через штатный API и переподключается через минуту. Повторный отказ свежей сессии, неверный пароль, MFA/2FA, бан и AFK-kick требуют вмешательства и завершают процесс с кодом `78`. systemd перезапускает аварийно завершившийся процесс через 60 секунд (`Restart=on-failure`), но код `78` исключён через `RestartPreventExitStatus`. Ручная остановка сервиса остаётся остановкой. Отсутствие лимита попыток не гарантирует непрерывность при недоступности MCSkill или ручной проверке аккаунта.

```bash
sudo sh deploy/check-vps.sh
sudo systemctl stop mcskill-afk       # SIGTERM, закрытие TCP и таймеров
sudo systemctl start mcskill-afk
sudo journalctl -u mcskill-afk --since '1 hour ago'
```

`metrics` раз в минуту содержит RSS/heap, число входящих пакетов и KeepAlive. Успешный вход обозначается `world_ready`. Отсутствие графики не исключает серверного AFK-kick: клиент соблюдает его и не маскирует активность.

Для проверки восстановления на VPS после `world_ready` кратковременно прервите **только исходящее соединение клиента с игровым сервером** средствами своей инфраструктуры и восстановите сеть. Дождитесь `reconnecting`, повторного `world_ready` и роста `keepAlives`; не блокируйте собственный SSH. Повторные входы через сеть могут требовать ручной авторизации нового IP. Автотест восстановления использует локальный TCP-сервер.

## Обновление данных входа

Для нового сервиса с паролем:

```bash
sudo systemctl stop mcskill-afk
./start.sh --setup                   # новые данные, затем Y
bash install-ubuntu.sh --service
sudo systemctl start mcskill-afk
```

При MFA/2FA или подтверждении нового устройства выполните требуемые действия в официальном лаунчере. Если API не разрешает вход с VPS, потребуется поддержка MCSkill: клиент не обходит проверки аккаунта.

Режим `./start.sh --session` остаётся доступен для импортированных сессий: обновите файл через `tools/import-session.js`, установите Unix-права `0600` (на Windows `tools/secure-session.ps1`) и перезапустите этот режим. Новый systemd unit использует файл логина/пароля, а не `session.json`.

## Совместимость модов

Manifest содержит **наблюдавшиеся локально** id/version из FML-отчёта, включая точные версии FML/Forge/MetaLib. Он не строится по названиям JAR и не зеркалит серверный список. Сетевой профиль реализует расширения MetaHandshakePatcher, MetaLib Join Game, FML VarShort и Hodgepodge length marker. Это декларация совместимости для данного headless-сценария, а не загрузка Java-модов: рецепты, блоки, GUI, сущности и произвольные mod RPC не исполняются.

Неизвестные plugin messages ограниченно читаются и отбрасываются, без выдуманных ответов. Если обновление сборки потребует новый обязательный обмен, понадобится исследовать и реализовать именно его. Не добавляйте фиктивные версии в manifest. Для повторного извлечения наблюдавшихся метаданных:

```powershell
python tools/extract-mods.py 'C:\path\fml-junk-earlystartup.log' observed-mods.json
```

Отчёт может содержать несколько исторических блоков: скрипт выбирает последнее наблюдавшееся значение каждого id; перед сменой профиля сверяйте его с текущей сборкой. В комплект включён manifest, с которым выполнен живой тест.

## Проверки и структура

```bash
npm ci --ignore-scripts
npm test
```

Тесты используют вымышленные токены и localhost: VarInt, кадры/частичный TCP, signed SHA-1, RSA PKCS#1 v1.5, AES-CFB8 (NIST), Login State/Disconnect, настоящий зашифрованный mock login + FML + мир + KeepAlive, закрытие сокета по AbortSignal, backoff и восстановление после реального обрыва локального TCP.

Отдельная проверка с настоящим аккаунтом: `node --max-old-space-size=192 tools/verify-live-reconnect.js`. Она делает вход, через 15 секунд после готовности намеренно закрывает **свой** TCP-сокет, ждёт заданный интервал (по умолчанию минуту), входит повторно и проверяет ещё минуту KeepAlive. Запускайте только при закрытой игре и остановленном сервисе. Токены она не выводит; итог содержит время, RSS и суммарное CPU-время процесса. Это проверка восстановления игрового соединения, а не проверка сети или systemd самого VPS.

`src/config.js` — ConfigProvider/SessionProvider; `codec.js` — framing/Reader; `encryption.js` — SHA/RSA/AES; `auth.js` — McSkillSessionService; `connection.js` — соединение/login; `forge.js` — FML; `game.js` — AFK; `reconnect.js` — повторы; `logger.js` — лог с allowlist полей; `cli.js` — режимы и сигналы. `deploy/` — установка и systemd, `tools/` — безопасный импорт и извлечение метаданных, `test/` — автоматические тесты.

Секреты, args, `.env`, JAR, декомпилированные файлы и временные исследовательские материалы исключены из Git. Полные содержимое пакетов, ответы Auth API и строки server Disconnect не логируются, поскольку могут содержать секреты. Сообщения `AUTH_REJECTED`, `PROTOCOL`, `NETWORK`, `SERVER_DISCONNECT` и `retry_limit` требуют соответствующей диагностики; внутренние ошибки протокола дополнены ID и размером пакета.

Для переноса исходников без Git можно выполнить `python tools/package.py`: архив `dist/mcskill-afk.zip` строится по явному списку публичных файлов, без сессии, args, `.git`, логов и JAR. После распаковки на Ubuntu используйте те же команды установки. Сессию передавайте отдельно через SSH.
